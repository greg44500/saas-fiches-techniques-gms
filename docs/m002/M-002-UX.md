## 1. Page Workspace Produits

Deux vues restent disponibles : `Référentiel global` et `Mon référentiel`.

Recherche :

```text
placeholder = Rechercher un produit…
```

Aucun vocabulaire interne `alias` n'est affiché.

## 2. Liste groupée

Un Produit apparaît une seule fois comme groupe avec sa catégorie.

Sous le groupe : références avec Conservation, État/transformation, unité, rendement et Actions. La Gamme n'est pas affichée dans le frontend actif.

Les actions `+ / −` sont liées à la variante. `Voir`/détail Produit reste au niveau du groupe.

Un Produit sans variante opérationnelle peut apparaître dans le Référentiel global avec `Aucune déclinaison exploitable` et une action d'enrichissement lorsque les droits le permettent.

La pagination principale est par Produit afin de ne jamais couper un groupe entre deux pages.

## 3. Recherche précise

`carotte`, `carotte râpée`, `bœuf paleron`, `agneau gigot tranché` doivent retrouver le Produit puis les variantes pertinentes.

Une suggestion prédictive doit rendre immédiatement lisibles le Produit et la Déclinaison. Une recherche précise ouvre ou réduit le groupe sur le résultat pertinent.

## 9. Enrichissement des Variétés et Caractéristiques

Le formulaire de création d'une Référence Produit distingue désormais clairement :

- une liste vide : `Aucune variété disponible` ou `Aucune valeur disponible` ;
- un choix volontairement omis alors que des valeurs existent : `Non renseigné`.

Le parcours d'enrichissement est une session multi-ajouts :

~~~text
Ajouter des valeurs
→ choisir directement le type métier
→ saisir une valeur
→ Ajouter
→ conserver le dialogue ouvert
→ saisir la valeur suivante
~~~

Les types proposés sont directement les libellés utilisateur :

- Variété ;
- Présentation ;
- Pièce / découpe ;
- Type commercial — masqué temporairement dans les nouveaux ajouts Workspace tant que sa définition métier n'est pas validée ;
- Calibre / format ;
- Couleur ;
- Désignation de qualité.

Le frontend ne demande plus à l'utilisateur de choisir d'abord « Caractéristique » puis un sous-type.

Chaque valeur reste atomique côté backend. Une Référence Produit sélectionne au maximum une valeur par type de Caractéristique ; le Produit peut en revanche posséder plusieurs valeurs disponibles pour chaque type.

Après chaque ajout :

- une valeur publiée automatiquement est marquée `Disponible` ;
- une valeur déjà existante est marquée `Existe déjà` ;
- une valeur provisoire soumise à gouvernance est marquée `À valider` et reste utilisable immédiatement dans le Workspace d'origine ;
- lorsqu'une valeur proche existe, l'interface propose explicitement `Utiliser <valeur>` ou `Créer quand même <saisie>` ;
- aucune faute mineure n'est fusionnée silencieusement ;
- la liste du formulaire parent est rafraîchie immédiatement ;
- le champ de saisie est vidé pour permettre l'ajout suivant.

Chaque ajout reste atomique : une seule valeur par soumission. Les saisies contenant plusieurs valeurs séparées par une virgule sont refusées dans ce flux.

Les explications permanentes du formulaire sont déplacées dans des icônes d'information avec infobulle. Les permissions M-002 restent inchangées ; la gouvernance backend distingue désormais lifecycle et statut de gouvernance.
