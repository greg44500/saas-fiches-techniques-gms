# M-002 — Contrat UX

**Statut : ALIGNÉ SUR CONTRIBUTION SEMI-AUTOMATIQUE ET DIMENSIONS STRUCTURÉES — 2026-09-24**

## 1. Page Workspace Produits

Route :

```text
/workspaces/:workspaceId/products
```

Deux vues :

```text
Référentiel global
Mon référentiel
```

### Référentiel global

Vue proposée en premier lorsque la capability `product_reference_access` est disponible.

Affiche les Produits et déclinaisons globales opérationnelles `ACTIVE`.

Actions :

- recherche prédictive puis recherche explicite ;
- filtrage par catégorie ;
- ouvrir le détail ;
- ajouter à Mon référentiel via `+` ;
- retirer de Mon référentiel via `−` lorsqu'une référence y est déjà présente ;
- créer un Produit lorsque l'existant ne convient pas.

La table affiche :

```text
Produit | Déclinaison | Gamme | Actions
```

Aucune colonne supplémentaire « Mon référentiel » ni colonne Statut ACTIVE redondante n'est affichée.

### Mon référentiel

Affiche uniquement les `WorkspaceProduct ACTIVE` dont le Produit et la déclinaison globale sont opérationnels.

Une référence retirée reste retrouvable dans le Référentiel global. Une référence globale archivée disparaît des listes opérationnelles sans être supprimée de l'historique.

Aucun filtre « Dans / Retiré » n'est nécessaire.

Une référence réelle n'a jamais le statut « En validation ». Une proposition peut en revanche être en revue via `ReferenceContribution`.

## 2. Création d'un Produit depuis un Workspace

Libellé :

```text
Créer un Produit
```

### Étape 1 — Vérifier l'existant

- exact match ;
- candidats proches ;
- synonymes métier et formes de recherche ;
- ouverture possible d'une référence existante.

### Étape 2 — Identité

- nom canonique ;
- catégorie obligatoire ;
- aucun champ Alias/Synonymes dans le formulaire Workspace ordinaire.

### Étape 3 — Première déclinaison

- Présentation initiale éventuelle ;
- Gamme obligatoire, backend-driven ;
- État / transformation lié à la Gamme ;
- unité de référence ;
- rendement facultatif.

Le champ Conservation n'est plus affiché.

Confirmation :

```text
Soumettre la proposition
```

Une nouvelle identité racine produit :

```text
ReferenceContribution PENDING_REVIEW
→ aucune référence publiée avant décision globale
```

Message utilisateur :

```text
Proposition envoyée en revue
```

Après approbation globale, le Produit devient disponible dans le Référentiel global. Son rattachement à Mon référentiel reste explicite.

## 3. Déclinaisons et enrichissement du référentiel

Pour un Produit existant :

- afficher les déclinaisons existantes ;
- charger Variétés et Caractéristiques depuis le backend ;
- sélectionner une Variété éventuelle ;
- sélectionner au plus une Caractéristique de chaque type ;
- choisir Gamme / État ;
- créer la déclinaison uniquement si sa signature est nouvelle.

Le formulaire de déclinaison n'invente pas de dimensions libres.

Action :

```text
Enrichir le référentiel
```

Elle soumet une Variété ou une Caractéristique au moteur de contribution :

```text
EXISTING
AUTO_PUBLISHABLE
REVIEW_REQUIRED
INVALID
```

Une dimension `REVIEW_REQUIRED` n'est sélectionnable qu'après décision de gouvernance.

## 4. Import Workspace

Parcours :

```text
Téléverser
→ associer les colonnes
→ prévisualiser
→ arbitrer / identifier la gouvernance nécessaire
→ confirmer
```

Dimensions M-002 mappables :

- Produit ;
- catégorie ;
- Variété ;
- Présentation ;
- type commercial ;
- calibre / format ;
- couleur ;
- désignation de qualité ;
- Gamme ;
- État / transformation ;
- unité ;
- rendement.

Les synonymes métier ne sont pas librement créés depuis l'import Workspace.

La prévisualisation distingue notamment :

- existant à rattacher ;
- nouvelle déclinaison ;
- dimension manquante ;
- ambiguïté ;
- revue du référentiel global ;
- ligne invalide ;
- colonnes M-003 détectées.

## 5. Administration globale du référentiel

Route :

```text
/product-reference
```

Navigation :

```text
Référentiel
Contributions
Catégories
```

L'accès dépend des permissions Application Global Produit.

### Référentiel

Avec `product:reference:manage` :

- créer/corriger/archiver/réactiver un Produit ;
- administrer Variétés et Caractéristiques ;
- corriger les synonymes métier gouvernés ;
- créer/corriger/archiver/réactiver une déclinaison structurée ;
- importer des Produits génériques ;
- consulter l'historique.

### Contributions

- filtrer par statut ;
- voir valeur proposée, type, origine Workspace, auteur et motif ;
- approuver ;
- refuser.

La revue concerne `ReferenceContribution`, jamais un pseudo-statut du Produit.

### Catégories

- créer ;
- renommer ;
- archiver/réactiver ;
- refuser l'archivage si une référence active l'utilise.

## 6. Vocabulaire utilisateur

À utiliser :

- Produit ;
- Variété ;
- Caractéristique ;
- Déclinaison ;
- Présentation ;
- Gamme ;
- État / transformation ;
- Synonymes métier ;
- Référentiel global ;
- Mon référentiel ;
- Contributions ;
- Soumettre la proposition ;
- Proposition envoyée en revue ;
- Approuver ;
- Refuser ;
- Archiver ;
- Réactiver.

À éviter :

- Alias dans les formulaires ordinaires ;
- En validation comme statut d'une référence ;
- À valider comme lifecycle Produit.

Le terme « catalogue » reste réservé aux catalogues fournisseurs M-003.

## 7. Responsive et QA

Vérifier desktop, grand écran, largeur intermédiaire et mobile raisonnable pour :

- tableaux ;
- pagination ;
- dialogs ;
- drawers ;
- selects/autocomplétions ;
- file Contributions ;
- formulaires structurés.

Toute anomalie visuelle démontrée doit être corrigée dans M-002 avant PR.
