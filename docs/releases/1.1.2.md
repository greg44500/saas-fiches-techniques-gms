# Core 1.1.2 — Frontend asynchronous interaction test stability

**Version :** 1.1.2  
**Canal :** stable  
**Date :** 2026-09-22  
**Tag cible :** `v1.1.2`

## Objet

`1.1.2` est une release PATCH rétrocompatible consacrée à la stabilité des tests frontend utilisant des primitives Base UI rendues de façon asynchrone via Portal.

Elle complète le harness jsdom stabilisé en `1.1.1` en supprimant les hypothèses synchrones restantes dans les scénarios où une option de Select ou le contenu d'un Popover peut être monté après l'ouverture.

Aucun code de production, endpoint HTTP ou contrat persistant n'est modifié.

## Correctifs de tests

### Select Base UI

Lorsqu'un test ouvre un Select puis recherche immédiatement sa première option, cette option est désormais attendue avec `findByRole`.

Le pattern devient :

```text
ouverture de la combobox
→ montage asynchrone du popup via Portal
→ attente sémantique de l'option
→ interaction
```

Les options sœurs déjà montées peuvent rester interrogées synchroniquement avec `getByRole`.

Les assertions d'absence continuent d'utiliser `queryByRole`.

### Popover Base UI

Les deux tests de sidebars qui ouvrent un Popover positionné via Portal attendent désormais la présence du lien ciblé avant interaction.

Aucune modification n'est apportée aux scénarios Collapsible qui ne dépendent pas d'un Portal.

### Stratégie de stabilisation

Le patch n'introduit aucun :

- `setTimeout` artificiel ;
- sleep ;
- retry manuel ;
- `waitFor` utilisé comme temporisation générique ;
- timeout Testing Library arbitrairement augmenté.

La synchronisation repose sur l'état sémantique réellement attendu par l'utilisateur.

## Périmètre audité

Le lot a audité les usages frontend pertinents de :
